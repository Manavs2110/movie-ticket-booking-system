sequenceDiagram
    autonumber
    actor U as Customer
    participant SM as SeatMapService
    participant R as Redis
    participant DB as PostgreSQL

    U->>SM: GET /shows/42/seats (If-None-Match)
    SM->>R: GET seatmap:42 (2 s micro-cache)
    alt cache hit
        SM-->>U: 304 if ETag matches, else 200 cached map
    else cache miss
        SM->>R: layout of the show's screen (cached)
        opt layout not cached
            SM->>DB: SELECT seats WHERE screen_id = ?
        end
        SM->>DB: SELECT seat_lock WHERE show_id = 42 AND (booked OR held_until > now())
        SM->>SM: merge → AVAILABLE / HELD / BOOKED / BLOCKED + prices + ETag
        SM->>R: SET seatmap:42 PX 2000
        SM-->>U: 200 seat map + ETag + nextChangeAt
    end

LLD 5 — sequence: lock seats (two layers) Open in Mermaid Live ↗ ↑ top

sequenceDiagram
    autonumber
    actor U as Customer
    participant RL as RateLimitFilter
    participant BS as BookingServiceImpl
    participant SH as TwoLayerSeatHoldService
    participant R as Redis
    participant DB as PostgreSQL

    U->>RL: POST /bookings {showId, seatIds}
    RL->>R: INCR rl:user:hold:minute (limit 10)
    RL->>BS: hold()
    BS->>DB: nextval('booking_id_seq')
    BS->>SH: reserve(showId, sortedSeatIds, bookingId)
    SH->>R: Lua ACQUIRE_ALL (TTL 30 s)
    alt any seat key exists
        BS-->>U: 409 SEATS_UNAVAILABLE (Postgres not touched)
    else keys set (or Redis bypassed by breaker)
        BS->>DB: TX: show FOR SHARE · checks · expire stale hold · price · insert booking HELD + items
        BS->>SH: claim(reservation, 10 min)
        SH->>DB: INSERT seat_lock … ON CONFLICT (sorted)
        alt claimed fewer than requested
            BS->>DB: ROLLBACK
            BS->>SH: abandon() → Redis release
            BS-->>U: 409 SEATS_UNAVAILABLE
        else committed
            SH->>R: after commit: extend keys to 10 min
            BS->>R: evict seatmap:showId
            BS-->>U: 201 HELD, holdExpiresAt
        end
    end

LLD 6 — sequence: pay and confirm Open in Mermaid Live ↗ ↑ top

sequenceDiagram
    autonumber
    actor U as Customer
    participant BS as BookingServiceImpl
    participant DB as PostgreSQL
    participant R as Redis
    participant PG as PaymentGateway

    U->>BS: POST /bookings/{id}/pay (Idempotency-Key)
    BS->>DB: payment by idempotency key? → replay the existing result
    BS->>DB: TX1: booking FOR UPDATE · show still SCHEDULED · extend seat_lock (≥ 5 min) · redeem discount · PAYMENT_PENDING · payment PENDING
    BS->>R: after commit: extend lock keys
    BS->>PG: charge (no transaction open)
    alt declined
        BS->>DB: TX: payment FAILED · booking HELD · give discount back
        BS-->>U: 402 PAYMENT_FAILED
    else approved
        BS->>DB: TX2: seat_lock booked = true · CONFIRMED · payment SUCCESS · outbox BOOKING_CONFIRMED · schedule SHOW_REMINDER (show − 2 h)
        alt confirm failed (lock lost / show cancelled)
            BS->>PG: refund full amount
            BS->>DB: TX3: booking EXPIRED + refund (100%, CONFIRM_FAILED) · payment REFUNDED · give discount back · release seats · outbox REFUND_PROCESSED
            BS-->>U: 409 HOLD_EXPIRED (refunded)
        else confirmed
            BS->>R: after commit: mark BOOKED until show end · evict seatmap
            BS-->>U: 200 CONFIRMED
        end
    end

        BS->>PG: refund(amount)
        BS->>DB: TX2: refund_status SUCCESS/FAILED · payment REFUNDED / PARTIALLY_REFUNDED · outbox REFUND_PROCESSED
    end
    BS-->>U: 200 CANCELLED + refund

    autonumber
    actor A as Admin
    participant BS as BookingServiceImpl
    participant DB as PostgreSQL
    participant R as Redis
    participant PG as PaymentGateway

    A->>BS: POST /admin/shows/{id}/cancel
    BS->>DB: TX: show FOR UPDATE (waits for in-flight holds) · status CANCELLED · version + 1
    loop each HELD / PAYMENT_PENDING / CONFIRMED booking (own transaction)
        BS->>DB: release seats · CANCELLED · refund 100% SHOW_CANCELLED · outbox SHOW_CANCELLED · cancel reminder
        opt was CONFIRMED
            BS->>PG: refund full amount
            BS->>DB: refund_status · payment REFUNDED
        end
    end
    BS->>R: releaseShow (all lock keys) · evict seatmap and listings
    BS-->>A: 200 ShowCancellationResult

LLD 9 — sequence: events → Kafka → notification Open in Mermaid Live ↗ ↑ top

sequenceDiagram
    autonumber
    participant DB as PostgreSQL (outbox_event)
    participant P as OutboxPublisher (every 2 s)
    participant K as Kafka (booking-events)
    participant C as NotificationConsumer
    participant N as NotificationSender

    loop every 2 s, repeat while batch is full
        P->>DB: SELECT status = NOT_STARTED AND next_attempt_at <= now() FOR UPDATE SKIP LOCKED
        P->>K: send (key = bookingId)
        alt acknowledged
            P->>DB: status IN_QUEUE, sent_at = now()
        else failed / timeout
            P->>DB: attempts + 1, next_attempt_at backoff (FAILED after max)
        end
    end
    K->>C: deliver BookingEventMessage
    C->>DB: TX: markProcessed (IN_QUEUE → PROCESSED)
    alt already PROCESSED or CANCELLED
        C-->>K: skip (duplicate)
    else reminder but booking no longer confirmed
        C-->>K: skip
    else
        C->>N: send (idempotency key = eventId)
    end
    Note over C,K: exception → TX rolls back → retry topics → dead-letter topic

LLD 10 — state machine: booking Open in Mermaid Live ↗ ↑ top

stateDiagram-v2
    [*] --> HELD : hold()
    HELD --> PAYMENT_PENDING : pay() — lock extended, discount redeemed
    PAYMENT_PENDING --> CONFIRMED : charge ok + seats confirmed
    PAYMENT_PENDING --> HELD : charge declined — discount given back
    PAYMENT_PENDING --> EXPIRED : confirm failed — auto-refund
    HELD --> EXPIRED : hold_expires_at passed (derived on read)
    HELD --> CANCELLED : cancel() / admin cancels show
    CONFIRMED --> CANCELLED : cancel() — policy refund / admin cancels show — 100%

stateDiagram-v2
    [*] --> AVAILABLE : no seat_lock row
    AVAILABLE --> HELD : claim → row inserted (held_until = now + 10 min)
    HELD --> BOOKED : confirm → booked = true
    HELD --> AVAILABLE : held_until passed (row stays, counts as free)
    HELD --> AVAILABLE : cancel / confirm failed → row deleted
    BOOKED --> AVAILABLE : booking cancelled → row deleted

LLD 12 — state machine: outbox event Open in Mermaid Live ↗ ↑ top

stateDiagram-v2
    [*] --> NOT_STARTED : written in the business transaction
    NOT_STARTED --> IN_QUEUE : published, Kafka acknowledged
    NOT_STARTED --> NOT_STARTED : publish failed — attempts + 1, backoff
    NOT_STARTED --> FAILED : max attempts reached
    NOT_STARTED --> CANCELLED : reminder of a cancelled booking
    IN_QUEUE --> PROCESSED : consumer handled it
